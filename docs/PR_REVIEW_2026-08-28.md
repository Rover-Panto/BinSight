# BinSight Cross-PR Review

Reviewed: 28 August 2026. All four PRs remain open. No contributor branch was changed or merged during this review. The findings below concern the reviewed heads, not a deployed system.

## Findings

### R1. [P1] PR1 treats a completed collection as fresh evidence indefinitely

Source: [planner.py:111-126](https://github.com/Rover-Panto/BinSight/blob/c256bd44a60d12628b9f0354879e1ad90a15ec1e/admin-portal/binsight/planner.py#L111-L126).

`PlanningService.evaluate` substitutes a completed-service record for delayed pre-collection readings. It writes zero fill/weight, high confidence, `stable_no_overflow`, and false stale/offline flags without expiring that substitute. A probe completed a mock route, advanced the decision clock by 72 hours without a new reading, and received `fill_pct=0`, `confidence_flag=true`, `stale_flag=false`, `offline_flag=false`, and `reading_age_hours=72`. That bin can disappear from inspection and collection consideration while its sensor is offline.

**Remedy:** preserve the service event as a separate operational fact. It may suppress immediate duplicate collection, but must not become a perpetual sensor observation. Apply age/health policy after the service override; use explicit post-service uncertainty and an inspection/fallback state after a bounded interval. Add a regression covering a completed collection followed by several days without telemetry.

### R2. [P1, integration] PR4 requires weight that PR2 does not produce

Sources: [PR4 features.py:69-75](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/src/features.py#L69-L75), [PR4 serve.py:62-74](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/src/serve.py#L62-L74), [PR2 schemas.py:26-34](https://github.com/Rover-Panto/BinSight/blob/e7055764b57663a9d916602d7b0e89f54df2eaa4/hardware_pipeline/cloud_backend/app/schemas.py#L26-L34).

PR4 requires `weight_kg`, `weight_rate_1h` and a weight-derived density feature. PR2 exposes fill, `estimated_density` and confidence, but no measured weight. A PR2-shaped history raises `KeyError: 'weight_kg'` before prediction. The budgeted load cells do not mean the current firmware has implemented weight measurement. PR1 correctly keeps weight null.

**Remedy:** provide and evaluate a fill-only model/feature pipeline for the current producer. Add a calibrated-weight variant only when the producer supplies it. Never convert PR2's pseudo-density into kilograms or fill missing weight with an invented measurement. Test the predictor using an actual PR2 response fixture. This blocks the proposed live connection, not the existing isolated citizen mock.

### R3. [P2] PR4's model file and evaluation metadata describe different models

Sources: [quick_train_rf.py:115](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/quick_train_rf.py#L115), [eval_results.json:32](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/models/eval_results.json#L32), [train.py:158-164](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/src/train.py#L158-L164).

The checked-in metadata selects `xgboost`. Inspection of the joblib header, without loading the pickle, identifies `sklearn.ensemble._forest.RandomForestRegressor`. The quick trainer overwrites the same `overflow_model.joblib` path without updating evaluation, features or importance. Consequently, the served artifact cannot be associated with the advertised selected-model result.

**Remedy:** use one training/export entry point, or separate versioned run directories for each experiment. Publish the artifact checksum, estimator type, ordered features, dependency versions, dataset/split identity and evaluation in one manifest. Test that the selected model and manifest agree. Keep large approved artifacts in a versioned release or artifact store rather than silently replacing one file.

### R4. [P2] PR1 permits future-trained state in a historical prediction

Source: [pr2_forecasting.py:883-898](https://github.com/Rover-Panto/BinSight/blob/c256bd44a60d12628b9f0354879e1ad90a15ec1e/admin-portal/binsight/pr2_forecasting.py#L883-L898).

The adapter filters future readings, but `_should_retrain` does not reject a saved model whose training cutoff is later than `decision_at`. A probe trained on 5 February and reused that state for a 21 January decision. It returned `retrained=false` and retained the 5 February training cutoff. A historical replay using the CLI's saved state can therefore incorporate knowledge that was unavailable at the decision time.

**Remedy:** validate both training time and training-data cutoff before using saved state. Reject or rebuild incompatible state from pre-cutoff evidence only. Include configuration/feature version in state compatibility and test historical replay after a later model has been saved.

### R5. [P2] PR4 uses the test set to choose the winning model

Sources: [train.py:60-75](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/src/train.py#L60-L75), [train.py:149-156](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/src/train.py#L149-L156).

`main` evaluates both candidates on `X_test` and then chooses the lowest test MAE. The validation set does not select the winner. The cycle split also shuffles cycles across the full period: the inspected train, validation and test sets all start on 1 January and extend to 31 March. Whole-cycle grouping avoids splitting one trajectory across sets, but does not establish the README's claimed chronological validation. Historical features also span cycles, so the claimed independence needs a stronger test.

**Remedy:** choose the model and threshold on validation data, then score one untouched chronological holdout. Purge cycles/label horizons crossing a cutoff and build historical features using only evidence available at each origin. Report critical recall alongside MAE and name the actual split used. This follows [scikit-learn's validation/test separation guidance](https://scikit-learn.org/stable/modules/cross_validation.html).

### R6. [P2] PR4's rate features fail on cold starts and telemetry gaps

Source: [features.py:67-75](https://github.com/Rover-Panto/BinSight/blob/313f76b2c8c0356f966018f591b1dec56b68a939/ml/src/features.py#L67-L75).

The feature builder derives one median sampling interval, then calculates hour windows by row offsets. One reading raises `ValueError: cannot convert float NaN to integer`; duplicate timestamps raise division by zero. With readings at 0, 0.5, 1 and 5 hours following an exact 10-percentage-point/hour trajectory, it reports a last one-hour rate of 45 instead of 10. Wi-Fi gaps and adaptive sampling make this a normal integration case, not just a malformed-input case.

**Remedy:** deduplicate using event identity, use real elapsed-time windows, and split rate calculations at verified collections. Return an explicit cold-start/unavailable result when history is insufficient. Test irregular sampling, missing intervals, collection resets and first startup, not only regular synthetic CSVs.

### R7. [P2] PR3's metadata validator permits invalid field types

Source: [relay.py:31-39](https://github.com/Rover-Panto/BinSight/blob/819ff37b41a78208ba1624ad0060f8bec0358346/recycling_vision/relay.py#L31-L39).

The dataclass annotations do not enforce runtime types. The validator accepts and serializes `sequence=true`, `object_count=1.5`, `is_simulation="false"` and an empty station ID. The main-owned decision policy rejects Boolean sequences and non-integer object counts. A payload that passes the advertised relay validator can therefore fail at the next boundary, while a string simulation flag can be misinterpreted by a consumer.

**Remedy:** enforce integer-not-Boolean counters, a real Boolean simulation flag, finite numeric confidence, non-empty identifiers and timezone-aware acquisition timestamps. Main must independently validate the request and session binding. Add malformed-field tests to the current three-test suite; do not move final acceptance into PR3.

### R8. [P2] PR1's localhost exception allows remote HTTP hosts

Source: [telemetry_client.py:45-46](https://github.com/Rover-Panto/BinSight/blob/c256bd44a60d12628b9f0354879e1ad90a15ec1e/admin-portal/binsight/telemetry_client.py#L45-L46).

The constructor uses string prefixes to allow plain HTTP for localhost. A probe accepted both `http://localhost.example.com` and `http://127.0.0.1.example.com`. These are not loopback hosts, yet requests would carry the configured API key over plain HTTP. No request was sent in this probe.

**Remedy:** parse the URL and validate its exact hostname/IP, scheme and credentials. Allow plain HTTP only for the documented loopback addresses. Add lookalike-host and user-info tests and define whether verified remote TLS may ever be disabled.

Raw telemetry storage and a read-only routing history cache are not inherently redundant. They serve different purposes. Keep source event identity, migrations, retention and replay checks; never delete existing stores just to remove a second file. The current 2,000-row producer history limit covers about 1.1 hours at two-second sampling, so the cache cannot recover gaps longer than that without producer pagination/export support.

Keep return-station rejection rate separate from measured contamination. Accepted/rejected classifier outputs alone do not establish true stream contamination; that KPI needs audited ground truth. PR1 should retain its unavailable status until the evidence exists.

## Integration Plan

1. **Agree the shared contract first.** PR1 owns route policy, route approvals and system KPI evaluation. PR4 owns candidate model training/evaluation and its adapter. Share target threshold, units, bin registry, event/cutoff provenance, forecast availability, model version and quality semantics.
2. **Fix PR1's new defects without replacing its completed work.** Retain its adapters and route lifecycle. Add the R1/R4/R8 regressions and keep live dispatch disabled until producer gates pass.
3. **Repair PR2 and finish one gateway.** Resolve its previous findings, implement three independently identified fill channels and combine the C3 modules. PR3 supplies the Grove adapter; it must not build a second full gateway image or rewrite routing.
4. **Correct and evaluate PR4 in isolation.** Fix R2/R3/R5/R6, handle cold start and invalid predictions, and prove deterministic inference from an actual PR2 fixture. Publish a model manifest. Run the same chronological and paired route evaluation as the baseline before promoting it. A lower ML error alone does not establish fuel savings.
5. **Keep the return system in main.** Main owns QR/session initiation, authenticated inference ingestion, server-side 0.70 confidence/stability policy, durable decisions, one RM0.20 mock credit and the citizen update client. The current main-owned Python policy is not an HTTP service. PR3's serializer is not an ESP transport. Neither PR1 nor PR4 should implement payouts or classify returned objects.
6. **Integrate with data preservation.** Retain existing citizen records/images and schema migrations. Back up telemetry/route stores before changing schema, replay saved fixtures through both event paths, verify no duplicate credits/dispatches, and test C3 resets and stale commands. Do not move proposal material back into Git.

Additional hardening: PR4 currently turns a stubbed non-finite model result into `risk_level="Low"` with a non-finite time and an unchanged positive sensor-confidence flag. Return `model_error`/unavailable with null time instead. Validate empty/multi-bin input, acquisition/ingestion cutoffs and model/feature versions; do not label sensor confidence as model confidence.
